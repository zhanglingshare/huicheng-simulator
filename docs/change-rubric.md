# 变更判据（change-rubric）

这套判据管三件事：**什么算更新、谁来更新、多久更新一次**。适用于惠城、博罗、惠东、惠阳、龙门、仲恺、大亚湾各项目。

核心原则：**跑了一次 ≠ 更新了一次**。只有结构、输入或误差真的变了，才动页面；否则保持上一版，连时间戳都不动。

---

## 一、三层，三种频率

| 层 | 内容 | 更新触发 | 频率 | 落盘文件 |
|---|---|---|---|---|
| 事实层 | 统计公报、官方指标 | 新一版公报 / 口径修订 | 季度·年度（一年几次） | `hc-viz/data.js`、各页 `data.json` |
| 关系层 | 主体、连接、网络结构 | 出现改变结构或连接状态的事件 | 每日巡检，网络平均几周变一次 | `data/relationship-changes-v1.json` 等三件套 |
| 模型层 | 情景、分布、结构指标 | 输入变 / 新实际值可回测 | 事件驱动重跑 + 季度回测 | `data/model-verify-v1.json` |

不按日全量重跑。按日全量重跑的产出，九成是重复，还会让页面天天动，读者分不清哪天真有事。

---

## 二、五类触发 → 四种动作

| 触发 | 判据 | 动作 | 页面表现 |
|---|---|---|---|
| 新统计公报 / 修订 | 官方原文、窗口内 | 更新事实卡 | 读数变、`as-of` 变、页脚写「本次修订：X 由 A 改为 B」 |
| 新事件改变结构 | 三条件全过（见第三节） | 追加 changes、节点或边 | 网络加一条边，卡片标「新增」 |
| 新事件不改结构 | 只满足前两条 | 进 sources，不改网络 | 来源列表加一条，网络不动 |
| 模型输入变 | `input_hash` 变 | 重跑 + diff + 误差标注 | 推演区数值变、版本号变 |
| 输入与事实都没变 | hash 相同 | **no-op**，不发布 | 时间戳不动 |

---

## 三、关系层三条件（缺一不动网）

1. 涉及两个已登记主体，节点或边上有 id；
2. 有一条能点开的原文；签约 ≠ 投产，规划 / 在建必须标不确定；
3. 改变的是**结构或连接状态**，不是单纯数字。

变更类型沿用现有七类：`new_entity` 新主体接入、`new_edge` 新连接形成、`strengthen` 增强、`weaken` 减弱、`exit` 主体退出、`break` 连接失效、`alternative` 替代路径。

删除边或节点必须留痕：标 `exit` / `break` 并写原因，不允许静默删除。

---

## 四、模型层三条规矩

1. **输入指纹**：每次跑记 `input_hash`（参数 + 数据版本 + 种子）。指纹不变不重跑，避免同一天两个结果。
2. **回测误差**：新一期实际值出来才做验算。相对误差超过 5% 标 `recalibrate`（待校准），并写明偏多少、偏在哪类；不允许悄悄调参数把结果调好看。
3. **输出带版本**：`model v1.x / as-of / 误差` 三个标记一起出现。模型数一律标 `not_forecast: true`。

模型数只准进「推演区」，不准进「事实卡」。事实数与推演数在视觉上必须能一眼分开。

---

## 五、diff 格式（每次发布附一行）

```json
{"at":"2026-11-10 22:25","added":2,"revised":1,"unchanged":29,
 "headline":"新增 C012（市一院三期用地预审，新主体）；修订 2023 GDP 口径"}
```

页面页脚展示这一行，读者据此判断这次更新值不值得看。

---

## 六、阈值（可调，改了要记）

| 项 | 阈值 | 越过后的动作 |
|---|---|---|
| 模型点估计相对误差 | 5% | 标 `recalibrate`，不隐藏 |
| 模型区间覆盖率（P10–P90） | 80% | 覆盖率低于 80% 视为区间过窄 |
| 关系层单次变更条数 | 无上限，但需逐条给原文 | 超过 5 条需在 note 写清核验窗口 |
| 事实层口径变更 | 一律显式标注 | 禁止只改数不写说明 |

---

## 七、谁动什么

- 抓取与初算（火山侧）：只产包，不碰 git；manifest 带每个文件 sha256 与 `input_hash`。
- 判断与落盘（豆包侧）：比 sha256 → 过六道门 → 只替换约定文件 → 发布 → 回拉核验。
- 页面模板：**不进流水线**，任何一次更新都不改 HTML 结构。
